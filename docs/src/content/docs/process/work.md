## Правила

- Одна задача — одна ветка, в `main` — только через pull request.
- Задача живёт в Issues; без ответственного и срока она не считается задачей.
- Коммиты короткие и по делу: `docs: ...`, `feat(ai): ...`, `test(sim): ...`,
  `fix(firmware): ...`. Индексируются только затронутые файлы; `git add .`
  не используется.
- Ревью — один человек, кроме автора. Мелкие правки документации можно
  мержить сразу.
- Секреты и личные данные в репозиторий не попадают.
- В git — только текст и мелкие файлы. Тяжёлые артефакты,
  бинарные модели и CAD-сборки — в Releases; гейт отвергает файлы больше
  2 МБ и бинарные расширения.
- Документация не содержит упоминаний чатов, моделей и инструментов
  генерации: источник числа — файл, тест или отчёт.

## Что проверять перед коммитом

1. Сборку сайта и локальные ссылки: `bun run build` в `docs/` и `link-check`
   из `.github/workflows/guard.yml`.
2. Лицензии: `license-gate` требует `GPL-3.0-or-later` в `LICENSE`, SPDX и
   манифестах; несовместимое объявление — жёсткая ошибка.
3. Соответствующие тесты и линтеры репозитория — см.
   [запуск и проверку](/potok-m/docs/project/run/).
4. `git diff --check` на затронутых путях.

## Где что обсуждать

Интерфейсные решения фиксируются ADR в
[разделе решений](/potok-m/docs/process/decisions/), термины — в
[глоссарии](/potok-m/docs/process/glossary/), восстановление процедуры — в
[запуске и проверке](/potok-m/docs/project/run/). Изменения кода — в канонических
репозиториях по [карте](/potok-m/docs/project/architecture/).

Собственный код — `GPL-3.0-or-later`, подробности — в
[лицензии](/potok-m/docs/project/licenses/).

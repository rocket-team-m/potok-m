Единственный источник формата — `uart.yaml`. Генератор делает из него
C-структуры, Python-парсер и Rust-библиотеку, поэтому прошивка, симулятор и
разбор логов читают одни и те же байты. Гейт `cargo run -p potok-generator --
--check` проверяет, что сгенерированные файлы не разошлись с описанием.

## Кадры

| Профиль | Направление | Размер | Magic |
| --- | --- | ---: | --- |
| Полный (compat) | запрос | 56 Б | `0x504D` |
| Полный (compat) | ответ | 14 Б | `0x5250` |
| Облегчённый (lowlat) | запрос | 42 Б | `0x4C54` |
| Облегчённый (lowlat) | ответ | 16 Б | `0x4C52` |

Байты упаковываются в явном little-endian порядке, никогда не `memcpy`
структуры: выравнивание хоста и STM32 не должно попадать в провод. Декодер
проверяет поля в порядке `magic → CRC → phase → version`.

Запрос несёт время, фазу, гиро, аксель, магнитометр, высоту, Pitot и флаги;
ответ — две поправки, confidence, `ai_healthy` и флаги. Числа квантуются по
фиксированным масштабам, объявленным в генераторе.

## CRC и seq

CRC-16/CCITT-FALSE: полином `0x1021`, init `0xFFFF`, без отражения, xorout 0;
считается по всем байтам кадра, кроме последних двух. Контрольная строка
«123456789» даёт `0x29B1`, пустой вход — `0xFFFF`. Первое наблюдение задаёт опорный номер,
дубликаты отвергаются, а forward-прыжок принимается только в пределах окна
(по умолчанию 64, допустимый диапазон `1..=0x7fff`). Арифметика по модулю:
`0xFFFF → 0` — прыжок на один, а обратный переход — вне окна. Отвергнутое
наблюдение не двигает состояние.

Коды ошибок одинаковы в C и Rust: `OK = 0`, `BUFFER = -1`, `MAGIC = -2`,
`CRC = -3`, `PHASE = -4`, `VERSION = -5`.

## Кросс-языковой golden

Четыре кадра зафиксированы в трёх реализациях независимо: C-эталон
`stm32/tests/golden_harness.c` компилируется жёстко
(`cc -std=c11 -Wall -Wextra -Werror`), Python использует сгенерированный
`protocol.py`, Rust запускает три golden-теста по именам. Скрипт
`stm32/tests/check_golden.sh` имеет режимы `all`, `self-test`, `license`,
`yaml`, `c`, `python`, `rust`. Негативный контроль с испорченным байтом
подтверждает, что компаратор действительно отказывает.

C-эталон `protocol_ref.{c,h}` — самостоятельная реализация для встраиваемого
кода: без `malloc`, VLAs и динамического состояния, все буферы
принадлежат вызывающему. Тест сравнивает его с сгенерированным `protocol.h` в
обе стороны: каждый кадр кодируется обеими реализациями и сравнивается
побайтово, затем каждая декодирует байты другой.

## Границы

Код протокола собирается в `no_std` для `thumbv7em-none-eabihf`, не зависит
от `std::error::Error` без одноимённой фичи и не знает ничего о пинах,
UART-инстансах и DMA-каналах — это ответственность прошивки. Подробности — в
[встраиваемых системах](/potok-m/docs/protocol/embedded/).

Источник: `PROTO01.md`, `POLISH-PROTO.md`, `B10-report.md`,
`golden_harness.c`, `uart.yaml`.

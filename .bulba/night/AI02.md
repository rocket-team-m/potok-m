## What the test pins

The AI repo has no production Python dispatch module: the guard was built as a
pure function (B02) and the dispatch contract lives in `SPEC_STUDENT.md` §"Правила
dispatch" plus the edge Rust mirror (B15). The test wires the real pieces at the
seam — `StatefulTCN.step()` produces a two-channel bounded correction and a
sigmoid confidence, a test-local `_dispatch()` screens them through
`potok_ai.watchguard.guard`, and only an accepted + healthy + valid-sensor
decision forwards the model command; every other case emits zeros.

- **Real outputs, real decisions** — a deterministic student stream is fed
  through a permissive config (every tick `OK`, dispatched command equals the
  model correction, chain carries `last_command`) and a strict one (real
  confidences below 0.99 → `LOW_CONFIDENCE`, zero command).
- **Latch/reset** — three consecutive confidence rejections latch; a confidently
  proposed real correction stays vetoed with `LATCHED` and zero output;
  `reset()` clears it and the same output is dispatched.
- **Finite checks** — NaN, +inf and −inf injected into a real correction channel
  or into confidence all produce `NON_FINITE` with a finite `(0.0, 0.0)` command,
  one miss, no rate reference, and no mutation of the source tensor.
- **No eval corruption** — held-out 14-feature episodes are screened tick by
  tick: frames are byte-identical afterwards, guarded and plain model passes
  give bit-identical outputs and hidden state, a fresh state accepts every tick,
  and a latched state zeroes only the dispatch command without changing the eval
  outputs.
- **Dispatch veto** — `sensors_valid=False` and `ai_healthy=False` force a zero
  command even when the guard itself accepts (the B02 `ai_healthy` AND rule).

Fixtures use private `torch.Generator`s and `np.random.default_rng` only; no
global RNG, clock or hardware dependency.

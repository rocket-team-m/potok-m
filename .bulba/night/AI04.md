## What the file tests

1. **Exact MAC** — pins `mac_breakdown()` (`stem 22_400`, `depthwise_conv 4_800`, `state_in 12_800`, `state_out 12_800`, `head 96`) and `analytical_mac() == 52_896`; asserts analytical total equals the sum of the breakdown. For two configurations (default batch 2, and a non-default `loops=2, window=7, kernel=5, rank=3, in_features=4, width=16` case) it attaches forward hooks to all five multiply-bearing modules and asserts the runtime-counted MACs equal the analytical breakdown — the count is checked against executed ops, not only against a literal.

2. **Deterministic p50/p99** — a private, pure `_percentile(samples, q)` (linear interpolation, numpy `method="linear"` convention). It is pinned on `1..9` (`p50 == 5.0`, `p99 == 8.92`), cross-checked against `numpy.percentile`, asserted order-independent and bit-identical on repeated calls, and its two validation errors are gated.

3. **CPU-only benchmark** — the model and a privately seeded input are asserted to live on CPU. With one thread (fixture saves/restores `torch.get_num_threads()`), it runs 3 warmups + 32 timed inferences and reports p50/p99 as a deterministic function of the raw samples. Assertions are structural only: sample count fixed, samples positive and finite, `0 < p50 <= p99 < inf`, statistic recomputes identically, and two forward passes on the same input are bit-identical. No machine-specific wall-clock threshold, so the test is not flaky.

The module docstring explicitly disclaims any architecture, accuracy or "faster than" claim.

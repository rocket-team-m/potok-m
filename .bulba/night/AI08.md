## What the test gates

One test, `test_engine_100_epoch_v3_hard_gate`:

1. **Tiny but version-correct v3 fixture** — 6 synthetic episodes × 24 frames:
   two training scenarios (0, 1, two episodes each) and one held-out scenario
   (16, two episodes). Each target carries the 6 v3 columns; `g_accel` is filled
   so `Episode.command_target()` returns the authoritative `[g_accel_y,
   -g_accel_x]` fin demand (physics baseline + a deterministic learnable
   residual), not the legacy diagnostic `g_theta`.
2. **Held-out untouched** — a spy on `LRSAdapter.batches` asserts every episode
   handed to training is non-held-out and not scenario 16; the whole validation
   file's SHA-256 is compared before and after both runs. The held-out scenario
   is read only by the engine's evaluation/calibration path, as specified.
3. **100 epochs, twice, same seed** — the real CLI is driven with
   `--model lrs --stage train --device cpu --epochs 100 --seed 1 --calibrate`.
   Both `metrics.json` reports must be exactly equal, which pins determinism at
   the full epoch budget, not at a smoke-step budget.
4. **Numeric hard gates from SPEC_ENGINE_IDEAL.md §4-5** —
   `ratio <= GENERALISATION_LIMIT` (1.25) and
   `0 <= ece <= DEFAULT_TARGET_ECE` (0.05), plus finite, positive RMSEs and a
   matching `calibration.json` (`n > 0`, threshold in range, same config hash).

## Measured on this box (seed 1, config hash `623c949c1423acf3`)

| metric | value | gate |
|---|---|---|
| RMSE train | 0.08108376983235296 | > 0 |
| RMSE held-out | 0.08573792371783993 | > 0 |
| ratio | **1.0573993278199791** | <= 1.25 |
| ECE (calibrated) | **1.11e-16** | <= 0.05 |
| ECE raw | 0.1981068151264721 | — |
| calibration | isotonic, n=26, threshold 0.5114 | n > 0 |

Two runs with the same seed produced byte-identical metric dicts. The held-out
file hash was unchanged.

**Honest caveat:** ECE is measured in-sample on 26 held-out windows and the
isotonic map can fit that many samples almost perfectly, so 1e-16 is a wire-up
check (the calibrator ran and improved a miscalibrated head), not evidence of
out-of-sample calibration quality. The generalisation evidence in this test is
the ratio gate, which compares genuinely unseen scenarios against training
scenarios at the same window and epoch budget.

## What the test pins

The repo has no separate Python "target export" writer: the canonical v3 target
export is the simulator's `validation.bin` v3 (`POTOKSIM`, six target columns,
the last two being `g_accel_y`/`g_accel_x`). The test builds those bytes
deterministically in memory and loads them through the production readers
(`potok_ai.data.read_validation`, `potok_ai.data_v3.read_targets`), mirroring the
pattern in `tests/test_data_v3.py`.

- **Deterministic** — two identical exports are byte-equal, have equal SHA-256,
  and load to equal `command` / `g_theta` arrays.
- **SHA** — export digest is a stable 32-byte raw SHA-256; flipping a byte in a
  `g_accel` column changes the digest and the loaded command. A second gate uses
  the real `export_model`/`load_export` path: byte-identical re-export, trailer
  equals `sha256(payload)`, and a tampered file raises `ValueError("checksum")`.
- **g_accel provenance** — loaded record is `version == 3`, `authoritative`, and
  its training target is exactly `[g_accel_y, -g_accel_x]` at every frame;
  `authoritative_command` / `authoritative_target` / `diagnostic_target` agree
  with the loaded record. Changing the `g_theta` columns leaves the command
  untouched, and vice versa.
- **No g_theta promotion** — a v1/v2 (four-column) export has `command is None`,
  `authoritative is False`, and both `training_target` and
  `authoritative_target` fail loudly with "diagnostic"; the angle target stays
  available only via `diagnostic_target`. Version/target-width mismatches
  (v3 with four columns, v2 with six) are refused.
